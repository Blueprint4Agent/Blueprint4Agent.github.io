# 런타임 모드

`APP_MODE`는 제품 동작을 선택합니다. `development`는 개발용 도구를 제공하고, `production`은 최종 사용자에게 필요한 기능만 제공합니다. 텔레메트리 라벨인 `APP_ENV`나 Vite 빌드 모드와는 별개입니다.

|               |                                                                                  |
| ------------- | -------------------------------------------------------------------------------- |
| **설정**      | `APP_MODE=development\|production`                                               |
| **기본값**    | `src/backend/.env.example`은 `development`, `docker/.env.example`은 `production` |
| **노출 위치** | `GET /config`의 `app_mode` 필드(B4React가 읽음)                                  |
| **요구 사항** | `production`은 `LOGIN_ENABLED=true`가 필요                                       |

알 수 없는 모드이거나 로그인이 꺼진 운영 모드는 설정 검증에서 실패하며 서버가 시작되지 않습니다. 배포마다 모드를 명시하고, 백엔드와 고정된 B4React를 함께 배포해 `/config` 계약을 맞춥니다.

## 모드별 제공 기능

| 동작                            | 개발                           | 운영                          |
| ------------------------------- | ------------------------------ | ----------------------------- |
| 기본 페이지                     | `/home`                        | `/home`                       |
| GitHub·사용 가이드 링크         | 프로필 컨트롤 옆에 표시        | 숨김                          |
| 후원 링크(Buy Me a Coffee)      | 빌드 시 켠 경우 표시           | 켜져 있어도 숨김              |
| 모양 설정의 레이아웃 미리보기   | 사용 가능, 브라우저별 저장     | 숨김, 저장된 미리보기 무시    |
| 컴포넌트 쇼케이스               | `/show-case` 별도 메뉴         | 직접 URL은 `/home`으로 이동   |
| 로그인 비활성 부트스트랩 사용자 | `LOGIN_ENABLED=false`에서 허용 | 거부(이전에 발급된 토큰 포함) |
| 개인 API 키                     | 사용 가능                      | 사용 가능                     |
| 스타일 스튜디오                 | 루프백 전용 로컬 도구          | 포함되지 않음                 |

런타임 제어는 공유 빌드에서 쇼케이스 JavaScript를 제거하지 않으며, 메뉴와 라우트만 제어합니다.

## 운영 서명 키 \{#production-signing-key\}

운영 모드에서 `SECRET_KEY`는 고유한 무작위 값이어야 합니다. 시작 시와 배포 사전 점검에서 빈 키, 예시 플레이스홀더(`CHANGE_ME...`), 앞뒤 공백, 알고리즘이 요구하는 길이보다 짧은 키를 거부합니다.

| `ALGORITHM`   | 최소 길이      |
| ------------- | -------------- |
| `HS256`(기본) | UTF-8 32바이트 |
| `HS384`       | UTF-8 48바이트 |
| `HS512`       | UTF-8 64바이트 |

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

`make docker-init`과 `make project-init`은 키를 생성해 공개된 플레이스홀더를 바꾸지만, 이미 설정된 키는 유지합니다. 길이 검사로 엔트로피를 증명할 수는 없습니다. 동작 중인 키는 함부로 교체하지 않습니다. JWT에 서명하고 대기 중인 메일 수신자 암호화 키 같은 다른 키의 바탕이 되므로, 교체하면 발급된 토큰과 키에서 파생된 데이터가 무효가 됩니다. 개발 모드는 예시 키를 계속 허용합니다.

## 부트스트랩 계정

로그인 비활성 개발 모드는 비밀번호가 없는 전용 부트스트랩 계정을 사용합니다.

- 일반 계정이 이미 `BOOTSTRAP_USER_EMAIL`을 쓰고 있거나 부트스트랩 계정의 역할이 바뀌었다면 시작이 실패합니다. 기존 계정을 자동으로 승격하지 않습니다.
- 부트스트랩 액세스 토큰이 만료되면 `/config`가 새 토큰을 발급하고, 동시에 발생한 `401` 응답은 한 번의 갱신을 공유합니다.
- 운영 모드는 부트스트랩 계정을 만들지 않으며 해당 계정의 Bearer 세션과 API 키를 거부합니다. 데이터는 삭제하거나 변환하지 않고 보존합니다. 운영에서는 별도의 실제 계정을 사용합니다.

## 기능 스위치

기능 스위치는 보이는 UI와 직접 API 호출을 함께 제어합니다. 값을 바꾸면 재시작해야 합니다.

| 스위치           | 꺼져 있을 때                                                                                                                                                                                                |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `STRIPE_ENABLED` | `/config`의 `billing_enabled=false`. 결제 메뉴, 설정, `/plans`, 요금제 배지가 사라지고 결제 훅은 요청을 보내지 않습니다. 직접 URL은 홈 또는 일반 설정으로 이동합니다. 기존 Stripe 구독은 해지되지 않습니다. |
| `EMAIL_ENABLED`  | 이메일 전용 라우트를 숨기고, 직접 이메일 인증 요청은 토큰을 소비하지 않고 거부합니다. 비밀번호 가입·로그인은 계속 동작하며 새 계정은 즉시 인증됩니다.                                                       |
| `OAUTH_ENABLED`  | OAuth 버튼과 연결된 제공자 정보를 숨깁니다. 콜백은 state를 소비하기 전에 현재 설정을 확인합니다.                                                                                                            |
| `LOGIN_ENABLED`  | 가입, 토큰 갱신, 이메일·OAuth 진입 요청을 I/O 이전에 거부합니다.                                                                                                                                            |

## 런타임 표시 설정

이 설정은 시작 시 읽혀 `GET /config`로 노출됩니다. 같은 이미지가 모든 값을 제공하므로, 바꾸려면 컨테이너를 재생성하고 브라우저를 새로고침합니다.

| 설정           | `/config` 필드 | 값                                   | 효과                                                                    |
| -------------- | -------------- | ------------------------------------ | ----------------------------------------------------------------------- |
| `APP_LAYOUT`   | `app_layout`   | `sidebar`(기본), `topnav`, `focused` | 앱 셸. [레이아웃](/docs/features/settings-and-profile#layouts) 참고     |
| `DEMO_ENABLED` | `demo_enabled` | `false`(기본), `true`                | 공개 읽기 전용 [관리자 데모](/docs/features/admin-and-roles#admin-demo) |

알 수 없는 `APP_LAYOUT`은 설정 검증에서 실패합니다. `/config`는 [basePath](/docs/environment/deployment#base-path) 배포를 위해 `api_base_path`와 `frontend_base_path`도 반환합니다.

## 모드 전환

1. 백엔드 또는 Docker `.env`에서 `APP_MODE`를 설정합니다(운영은 `LOGIN_ENABLED=true`도 필요).
2. 백엔드를 재시작합니다. 모드 전환은 계정·결제 데이터를 바꾸지 않습니다.
3. 기존 개발용 부트스트랩 계정을 정리하기 전에 연결된 데이터를 확인합니다.

전체 정책은 B4FastAPI의 `notes/runtime-modes-rbac.md`, 역할별 권한은 [관리자와 역할](/docs/features/admin-and-roles)을 참고합니다.
