# 문의하기

사용자는 설정에서 비공개 문의를 등록하고 대화를 이어 갑니다. 관리자는 관리자 패널에서 모든 문의를 확인하고 답글을 쓰며 상태를 바꿉니다. 외부 이메일 서비스는 필요하지 않습니다.

|                 |                                                  |
| --------------- | ------------------------------------------------ |
| **사용**        | 로그인 사용자에게 항상 제공                      |
| **사용자 화면** | **설정 → 문의하기**(`/settings?section=support`) |
| **관리자 화면** | `/admin/inquiries`                               |
| **엔드포인트**  | `/api/v1/inquiries`                              |
| **알림**        | [알림함](/docs/features/notifications)           |

## 엔드포인트

| 메서드와 경로                          | 권한               | 동작                                 |
| -------------------------------------- | ------------------ | ------------------------------------ |
| `GET /api/v1/inquiries`                | 로그인 사용자      | 본인 문의 목록, 상태 필터            |
| `POST /api/v1/inquiries`               | 로그인 사용자      | 제목과 본문으로 문의 등록            |
| `GET /api/v1/inquiries/{id}`           | 작성자 또는 관리자 | 문의와 메시지 조회                   |
| `POST /api/v1/inquiries/{id}/messages` | 작성자 또는 관리자 | 메시지 추가                          |
| `GET /api/v1/inquiries/admin`          | 관리자             | 모든 문의 목록                       |
| `PATCH /api/v1/inquiries/{id}/status`  | 관리자             | `open`, `in_progress`, `closed` 설정 |

- 권한은 서버에서 검사합니다. 볼 수 없는 문의는 404를 반환하며 모든 응답은 `no-store`입니다.
- 매니저는 일반 사용자 권한만 가지므로 다른 사용자의 문의를 볼 수 없습니다.
- 목록은 페이지 단위입니다(`page_size` 1–100, 기본 20).

## 규칙

| 규칙            | 값                                                |
| --------------- | ------------------------------------------------- |
| 제목            | 최대 160자                                        |
| 본문, 메시지    | 최대 4,000자, 텍스트만, 첨부 없음                 |
| 스레드당 메시지 | 200개                                             |
| 종료된 문의     | 새 메시지를 거부하며 관리자가 다시 열 수 있음     |
| 재시도          | 클라이언트 요청 UUID로 같은 등록·답글의 중복 방지 |

PostgreSQL에서는 사용자별·스레드별 잠금으로 쓰기를 직렬화합니다. 각 문의 변경과 알림함 기록은 하나의 트랜잭션으로 커밋됩니다.

| 이벤트    | 알림 대상            |
| --------- | -------------------- |
| 새 문의   | 작성자와 활성 관리자 |
| 답글      | 상대방               |
| 상태 변경 | 작성자               |

계정을 삭제하면 본인 문의가 삭제됩니다. 관리자 계정이 삭제되면 남아 있는 답글에서 해당 관리자의 식별 정보가 제거됩니다.

## 프론트엔드

- 문의를 등록하면 토스트로 확인합니다. 전송에 실패하면 입력 내용을 유지하고 성공 피드백을 보이지 않습니다.
- 작성자는 **추가 내용**을 쓰고, 관리자에게만 **답변 내용**이 보여 양쪽을 쉽게 구분할 수 있습니다.
- `inbox.changed`가 도착하면 화면이 API에서 다시 읽습니다. 이벤트에는 내용이 없습니다.

## 코드

- 백엔드: `routers/v1/inquiry.py`, `services/inquiry.py`, `models/inquiry.py`
- 프론트엔드: `src/frontend`의 문의 설정 섹션과 `/admin/inquiries`
