# 홈, 설정과 프로필

B4React는 랜딩 홈, 세 가지 배포 레이아웃, 설정 작업 공간, 계정·프로필 편집, 라이트·다크 테마, 사용자 지정 키보드 단축키, 토스트 피드백을 갖춘 완성된 앱 셸을 제공합니다.

## 홈

`/home`은 두 [런타임 모드](/docs/environment/runtime-modes) 모두의 기본 페이지입니다. `/`, `/dashboard`, 로그인 완료, 인증 대화상자 닫기, 페이지 복구는 모두 홈으로 이동합니다. 홈은 모든 [레이아웃](#layouts)에서 동작하는 제품 랜딩 페이지입니다.

| 영역      | 내용                                                                              |
| --------- | --------------------------------------------------------------------------------- |
| 소개      | 제목, GitHub·사용 가이드 링크, 옆에 놓인 제품 미리보기(좁은 화면에서는 세로 배치) |
| 미리보기  | 예시 데이터로 찍은 실제 화면: 사용자 관리, 서버 상태, 결제, 쇼케이스              |
| 기능      | _사용자를 위한 기본기_, _서비스 안에서의 경험_, *운영을 위한 준비*로 묶은 카드    |
| 개발 흐름 | 번호가 붙은 세 단계: 개발 환경 준비, 서비스 기능 개발, 검증하고 배포              |
| 활용 예시 | 구독형 서비스, 내부 업무 도구, 고객 포털, 제품 프로토타입                         |
| 계정 링크 | 로그인 상태와 역할로 거른 바로가기                                                |
| 푸터      | 같은 목적지와 역할 검사를 재사용하는 제품·자료·계정 열                            |

- **섹션 링크**는 화면, 기능, 개발 흐름, 활용 예시로 이동합니다. 상단 메뉴형과 미니멀형 레이아웃은 헤더 가운데에, 사이드바형은 떠 있는 캡슐에 표시합니다. 동작 줄이기 설정이 없으면 부드럽게 스크롤합니다.
- **미리보기**는 진행 표시줄과 함께 6초마다 전환되며, 마우스를 올리거나 포커스가 있어도 계속됩니다. 직접 일시정지, 확대 보기, 화면 밖이나 숨겨진 탭, 동작 줄이기 설정에서는 멈춥니다. **직접 열기**는 기존 역할 검사를 따릅니다.
- 스크린샷에는 실제 계정이나 서버 상태가 아닌 가상 데이터만 있으며, 기능 목록은 현재 켜진 기능이 아니라 블루프린트가 지원하는 기능을 설명합니다.

| 사용자         | 계정 링크                                                         |
| -------------- | ----------------------------------------------------------------- |
| 게스트         | **로그인** 진입점, 계정(`/login`으로), 결제(`/plans`로), 환경설정 |
| 로그인 사용자  | 계정, 결제, 알림함, 문의하기, 환경설정                            |
| 매니저, 관리자 | 사용자 목록 링크 추가                                             |

결제 링크는 결제가 켜져 있을 때만 보입니다. 게스트는 비공개 API를 요청하지 않습니다.

`src/components/layout`의 `MainPageTemplate`은 제품에 추가하는 설정형 메뉴 페이지를 위한 표현용 레이아웃으로 계속 제공됩니다.

| Prop                           | 용도                                                   |
| ------------------------------ | ------------------------------------------------------ |
| `title`, `description`, `icon` | 제목 영역                                              |
| `actions`                      | 기존 컴포넌트로 구성한 헤더 컨트롤                     |
| `menuLabel`, `menuItems`       | ID, 라우트, 제목, 아이콘을 가진 접근성 있는 내비게이션 |
| `menuLayout`                   | `list`(기본) 또는 반응형 `grid`                        |
| `children`                     | 추가 섹션, 목록, 카드, 로딩·빈 상태                    |

템플릿은 인증, API, 라우팅 상태, 저장소를 소유하지 않습니다. 이를 사용하는 페이지가 권한에 따라 항목을 거르고 훅으로 자체 데이터를 불러옵니다.

## 앱 셸

- 사이드바형 레이아웃: 접으면 48px, 펼치면 224px이며 200–360px 사이로 크기를 조절할 수 있습니다. 너비는 기억됩니다.
- 프로필 컨트롤과 연결 상태는 모든 레이아웃에서 사용할 수 있습니다. 개발 모드에서는 그 옆에 GitHub, 사용 가이드, 선택형 후원 링크가 있습니다.
- 결제가 켜져 있으면 프로필에 구독 등급이 표시되고, 프로필 메뉴에서 `/plans`를 엽니다.
- 프로필 메뉴에는 **프로필**, 바로 아래에 읽지 않은 개수 배지가 붙은 **알림함**([알림함](/docs/features/notifications) 참고), 매니저와 관리자용 **관리자 패널**이 있습니다. [관리자 데모](/docs/features/admin-and-roles#admin-demo)가 켜져 있으면 게스트를 포함한 다른 방문자에게는 **관리자 패널 (데모)**가 대신 보입니다.
- 모바일에서는 사이드바가 콘텐츠 위에 겹쳐지며 배경을 눌러 닫을 수 있습니다.
- 서버에 연결할 수 없을 때도 복구 패널이 같은 레이아웃 안에 표시됩니다.

## 레이아웃 \{#layouts\}

| `APP_LAYOUT`    | 셸                                                                                |
| --------------- | --------------------------------------------------------------------------------- |
| `sidebar`(기본) | 접고 크기를 조절할 수 있는 왼쪽 레일(사이드바형)                                  |
| `topnav`        | 가로 헤더의 전역 내비게이션(상단 메뉴형), 좁은 화면에서는 브랜드 왼쪽 메뉴 아이콘 |
| `focused`       | 투명한 소형 헤더(미니멀형), 브랜드 왼쪽 메뉴 아이콘이 작은 내비게이션 팝업을 엶   |

- 배포는 런타임 설정 `APP_LAYOUT`으로 레이아웃을 고르며, 이 값은 `GET /config`의 `app_layout`으로 노출됩니다. 같은 이미지가 세 가지를 모두 제공하므로 새 값으로 컨테이너를 재생성하고 브라우저를 새로고침하면 됩니다. 알 수 없는 값은 시작 시 검증에서 실패합니다. `src/service.config.ts`는 이 필드를 보내지 않는 제공자를 위한 대체값일 뿐입니다.
- 전역 내비게이션에는 홈과 개발 모드의 쇼케이스만 있으며 설정이나 관리자 섹션 목록은 들어가지 않습니다. 사이드바가 없으면 이 섹션들은 콘텐츠 옆의 박스형 열을 쓰고, 좁은 화면에서는 콘텐츠 위의 펼침 메뉴가 됩니다.
- 홈, 프로필, 알림함, 오류, 인증 페이지는 각자의 페이지 스타일을 유지합니다. `/plans`와 공개 `/about/` 페이지는 독립된 셸을 유지합니다.
- 서버가 `app_mode=development`를 보고하면 **설정 → 모양 → 레이아웃**에서 이 브라우저에서만 다른 레이아웃을 미리 볼 수 있고, 이 미리보기가 `APP_LAYOUT`보다 우선합니다. **서비스 기본값 사용**으로 지웁니다. 운영 모드는 저장된 미리보기를 무시하고 선택기를 숨깁니다. 열린 클라이언트는 새로고침할 때 바뀐 `APP_LAYOUT`을 반영합니다.

## 설정 섹션

| 섹션     | 대상                          | 내용                                                                        |
| -------- | ----------------------------- | --------------------------------------------------------------------------- |
| 일반     | 모두                          | 언어(영어, 한국어)                                                          |
| 모양     | 모두                          | 미리보기가 있는 시스템·라이트·다크 테마, 개발 모드의 레이아웃 미리보기      |
| 키보드   | 모두(편집은 로그인 사용자)    | 단축키 지정                                                                 |
| 계정     | 로그인 사용자                 | 이름, 이메일, 연결된 로그인 방식, 요금제, 비밀번호 변경, 계정 삭제          |
| 결제     | 로그인 사용자, 결제 활성화 시 | 요금제, 거래 내역, 청구 정보, 결제수단. [결제](/docs/features/billing) 참고 |
| 문의하기 | 로그인 사용자                 | 비공개 [문의](/docs/features/support)와 답변                                |
| 개발자   | 로그인 사용자                 | [API 키](/docs/features/api-keys)                                           |

섹션은 URL의 일부입니다(`/settings?section=...`). 이전의 `section=profile`은 계정 섹션을 엽니다. 게스트가 계정 전용 섹션을 열면 일반으로 이동하고, 결제가 꺼져 있으면 결제 섹션도 일반으로 이동합니다.

## 계정

**설정 → 계정**은 신원과 보안을 다룹니다.

- **이름**은 제자리에서 편집하며, 저장은 토스트로 확인하고 오류는 입력란 옆에 표시합니다.
- **이메일**, 연결된 로그인 제공자, 가입일, 현재 요금제를 보여줍니다.
- **비밀번호 변경**은 등록된 이메일로 6자리 코드를 보내는 모달에서 진행합니다. [인증](/docs/features/authentication#password-change)을 참고하세요.
- **계정 삭제**는 하단의 별도 섹션에 있으며 같은 이메일 코드 모달을 사용합니다. [인증](/docs/features/authentication#account-deletion)을 참고하세요.
- **프로필로 이동**은 프로필 페이지를 엽니다.

`EMAIL_ENABLED=false`이면 비밀번호 변경과 계정 삭제는 안내와 함께 비활성화되며, 이메일 인증을 건너뛰지 않습니다.

## 프로필 \{#profile\}

`/profile`은 로그인한 사용자 전용 비공개 페이지입니다. 사이드바 프로필 메뉴, 계정 섹션, <kbd>Mod</kbd> + <kbd>Shift</kbd> + <kbd>P</kbd>로 열며, 진입한 곳의 사이드바 레이아웃을 그대로 유지합니다. 공개 프로필은 없고 다른 사용자의 프로필을 볼 수도 없습니다.

| 항목        | 규칙                                                                                             |
| ----------- | ------------------------------------------------------------------------------------------------ |
| 사진        | 관리형 업로드, 즉시 저장. [오브젝트 스토리지](/docs/features/object-storage#profile-photos) 참고 |
| 이름        | 필수                                                                                             |
| 소개(Bio)   | 선택, 최대 100자, 줄바꿈 유지                                                                    |
| 국가, 지역  | 고정된 카탈로그(국가 249개, 하위 지역 4,387개)의 연동 드롭다운, 위치 정보는 사용하지 않음        |
| 가입일      | 읽기 전용                                                                                        |
| 현재 요금제 | 공유 구독 스냅샷 기준, 결제가 꺼져 있으면 Free                                                   |

- 이름, 소개, 위치는 페이지에서 바로 편집하거나 편집 모달에서 함께 편집합니다. 제자리 저장은 해당 항목만 변경하며, 저장에 실패하면 입력 중인 내용을 유지합니다. 제자리 편집기 바깥을 클릭하면 입력 중인 내용이 취소되며, 저장 버튼과 위치 드롭다운 같은 떠 있는 메뉴는 예외입니다.
- `GET/PATCH /api/v1/auth/me`가 유일한 기준입니다. `bio`와 `location`은 `null`로 지우고 생략하면 유지됩니다. 백엔드는 UI와 같은 국가·지역 조합을 검증합니다.
- 저장된 변경은 사이드바에 즉시 반영됩니다. 이미 열려 있는 다른 클라이언트는 다음 새로고침이나 로그인 후 반영됩니다.
- 페이지는 공용 상승 애니메이션으로 나타나며, 동작 줄이기 설정을 따릅니다.

## 키보드 단축키

| 동작          | 기본값                                                          |
| ------------- | --------------------------------------------------------------- |
| 사이드바 토글 | <kbd>Mod</kbd> + <kbd>B</kbd>                                   |
| 설정 열기     | <kbd>Mod</kbd> + <kbd>,</kbd>                                   |
| 프로필 열기   | <kbd>Mod</kbd> + <kbd>Shift</kbd> + <kbd>P</kbd>(로그인 사용자) |

<kbd>Mod</kbd>는 macOS에서는 Command, Windows와 Linux에서는 Control입니다.

단축키는 계정에 저장되므로(`GET/PATCH /auth/me`의 `keyboard_shortcuts`) 브라우저와 기기를 바꿔도 유지됩니다. 게스트는 기본값을 읽기 전용으로 봅니다. 프로필 단축키는 입력란에 입력 중이거나 대화상자가 열려 있으면 무시됩니다. 충돌하는 단축키는 거부되고, 저장이 확인된 경우에만 활성 단축키가 바뀌며, **초기화**는 기본값으로 되돌립니다. 이미 열려 있는 다른 클라이언트에는 새로고침이나 로그인 후 반영됩니다.

## 토스트와 피드백

명시적인 작업이 끝나면 화면 상단에 짧은 캡슐 토스트로 한 번 알립니다. 로그인·로그아웃, 가입, 인증 메일 재발송, 비밀번호 재설정, 프로필 변경, API 키 작업, 결제 확인, 비밀 값 복사가 해당됩니다. 입력 검증 오류는 입력란 옆에, 지속되는 안내는 `InlineMessage`로 표시하며, 토스트에는 비밀번호, 비밀 값, 토큰을 넣지 않습니다.

## 다국어

모든 UI 텍스트는 react-i18next로 영어와 한국어로 번역됩니다. 이메일은 사용자의 언어를 따릅니다.
